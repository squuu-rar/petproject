# Écho

Self-hosted музыкальный плеер «Écho» с персональной волной рекомендаций.

## Архитектура
- **`main.py`**: Точка входа FastAPI (REST API + раздача `static/` и стриминг аудио).
- **`db.py`**: Подключение к SQLite (`tracks.db`) и инициализация таблиц.
- **`scanner.py`** / **`importer.py`**: Модули сканирования директории с музыкой и пакетного импорта ID3/FLAC метаданных через `mutagen`.
- **`wave_engine.py`**: Алгоритм формирования автоочередности («Моя волна»).
- **`static/`**: Веб-интерфейс «Écho» (HTML/CSS/JS) для воспроизведения на ПК и смартфонах.

## Схема БД (SQLite)
- `tracks`: id, path, title, artist, album, genre, year, track_number, duration, cover_path, source, external_id, cache_path, liked, last_accessed.
- `history`: события `play`/`skip`/`finish`/`like`/`dislike`/`error`/`stop`, реально прослушанное время, длительность, доля прослушивания, вес сигнала, ID воспроизведения, контекст и версия алгоритма.
- `music_tag_cache`: теги исполнителя/трека и срок их актуальности.
- `playlists`: id, name, created_at.
- `playlist_tracks`: playlist_id, track_id, position.

## Экран «Моя волна»

Настройки открываются поверх плеера: справа на компьютере и снизу на экране
до 820 px. Закрываются кнопкой, кликом по фону или Escape; фокус возвращается
на «Настроить». Изменения применяются к следующим трекам, текущая песня продолжает играть.
На экране остаётся краткое описание потока, увеличенная обложка с мягким фоном
и блок «Далее»: три трека на компьютере, два на телефоне.

При загрузке кнопка сохраняет размер и подпись «Подбираем музыку». Через 12 секунд
появляется ручной повтор; он отменяет предыдущий клиентский запрос. Серверная
обработка уже отправленного запроса может завершиться, но её результат не меняет новую очередь.
Пустой результат и ошибка показываются отдельно, без автоматического цикла повторов.

`TrackRead.recommendation_reason` содержит объяснение только при известном источнике:
связь похожих исполнителей/треков или радио по конкретному треку. Для любимой песни
интерфейс показывает «Из ваших любимых»; без подтверждённого объяснения подпись скрыта.

## Как работает «Моя волна»

Профиль вкуса складывается из любимых треков, плейлистов, локальной коллекции,
дослушиваний и пропусков. Сам запуск трека не считается симпатией. Вклад событий
истории уменьшается по формуле `1 / (1 + возраст_в_днях / 30)`; вес истории
отдельного трека при выборке ограничен, чтобы повторы не вытесняли остальную коллекцию.

Для внешних рекомендаций используются YouTube Music Radio, поиск по знакомым
и похожим исполнителям и Last.fm (если задан API-ключ). Last.fm сначала ищет
похожие песни, затем использует похожих исполнителей при пустом результате.
Каналы выполняются параллельно. При сопоставлении песни с YouTube проверяются
исполнитель и название; контекстный поиск откатывается к поиску по исполнителю,
если вернул посторонние результаты.

Общий фильтр исключает недавние повторы, пропуски, дубликаты, караоке и треки
с известной длительностью вне 45–720 секунд. Пропуск исключает трек на три дня.
Исполнитель исключается при двух и более сильных отрицательных сигналах за два дня,
если их больше, чем положительных. Поздний пропуск и ошибка сети не блокируют исполнителя. Отдельно учитывается текущая сессия (45 минут).
Кандидаты ранжируются по профилю исполнителей, позитивным событиям сессии,
настроению и активности. При равных оценках сохраняется случайное разнообразие.

Для 20 треков целевые пропорции новых и знакомых: 17/3 по умолчанию, 5/15
в «Любимом», 19/1 в «Больше открытий». При нехватке коллекции очередь дополняется
новыми кандидатами; при менее пяти найденных внешних треках допускается больше
знакомых. Исполнители разносятся по очереди, если состав пула это позволяет.
Фильтр языка не снимается при пустой выдаче. В офлайн-режиме доступны только
существующие локальные файлы и файлы кэша; внешние рекомендации не запрашиваются.
Для маленькой коллекции допускается повтор недавно прослушанного трека, но
исключения по пропускам, языку, доступности и явно переданным ID сохраняются.

Это эвристическая система, без обученной модели и анализа аудиосигнала.
Настроение учитывает кэшированные жанровые теги вместе с названиями и жанром.
Явный языковой тег песни имеет приоритет над кириллицей в метаданных;
страна исполнителя не считается языком песни. При отсутствии надёжных тегов
сохраняются приблизительные правила по метаданным. Поведенческие тесты используют
подмены внешних сервисов и не измеряют субъективное качество рекомендаций.

## Очередь и обратная связь (wave-v3)

Фронтенд вызывает `POST /wave` с параметрами фильтров и `exclude_tracks`: списком
объектов с `id`, `external_id`, `artist`, `title` (до 2000 последних записей очереди).
Сервер исключает совпадения по любому идентификатору или нормализованной паре
исполнитель/название, включая офлайн-выборку. При недостатке внешних кандидатов
один раз пробует другие опорные треки. Фронтенд дополнительно проверяет всю
текущую очередь и дубли внутри ответа. Пустой результат не подменяется повторами.
Старый `GET /wave` сохранён для совместимости, но сам по себе не знает очередь клиента.

Лайк, «Не моё» и серия ранних пропусков обновляют будущую часть очереди после
сохранения событий. Текущий трек и уже проигранная часть сохраняются. Поздние ответы
от предыдущего запроса или режима игнорируются; обратная связь во время обновления
запускает следующий пересчёт. Кнопка пропуска не ждёт сетевого запроса, обновление
происходит в фоне. При сетевой ошибке прежняя будущая очередь сохраняется.

Плеер считает уникальные прослушанные интервалы аудио: паузы, буферизацию,
перемотку и повтор того же участка не прибавляет к доле прослушивания.
Длительность берётся из аудиоэлемента с запасным значением из метаданных.
`POST /history` принимает пропуски любой длительности. Для одной попытки воспроизведения
передаётся `playback_id`; повторная отправка события и повторный финальный исход
не увеличивают счётчики. При уходе со страницы финальное событие отправляется
через `sendBeacon`, когда браузер его поддерживает; доставка при аварийном закрытии
браузера не гарантируется.

Веса: запуск и техническая ошибка — 0; лайк — +3.5; «Не моё» — −4.
Ручной пропуск до 15 секунд или 25% — −3; до 50% — −1; от 50% до 80% — 0;
прослушивание от 80% — +2.5. При неизвестной длительности пропуск после 15 секунд
получает −1. Ошибка источника временно исключает только сам трек, не влияет
отрицательно на вкус. Старые события без новых полей сохраняют прежнюю трактовку.

## Теги

Используются [track.getTopTags](https://www.last.fm/api/show/track.getTopTags) и
[artist.getTopTags](https://www.last.fm/api/show/artist.getTopTags) при настроенном
`LASTFM_API_KEY`. Успешные непустые результаты хранятся в SQLite 30 дней, пустые —
сутки, ошибка API — 5 минут. За один этап обогащения запрашивается максимум 16
отсутствующих записей, по четыре одновременно, с тайм-аутом 2 секунды на запрос.
Остальные треки остаются допустимыми без тегов. В офлайн-режиме используется только кэш.
Теги — пользовательская разметка Last.fm, поэтому это улучшение признаков, а не
достоверное распознавание языка или анализ аудиосигнала.

## Метрики качества

`GET /wave/metrics?days=30` возвращает статистику за 1–365 дней, общую и по версии
алгоритма. Данные остаются в локальной SQLite; внешняя аналитика не используется.

- `plays`, `settled_plays`: попытки воспроизведения и попытки с финальным событием.
- `completion_rate`: доля завершённых попыток с прослушиванием от 80%, исключая ошибки.
- `early_skip_rate`: доля ранних ручных пропусков/«Не моё» среди завершённых попыток без ошибок.
- `error_rate`: доля технических ошибок среди завершённых попыток.
- `discovery_like_rate`: доля попыток проигрывания новых для коллекции треков с лайком.
- `mean_listen_ratio`: средняя доля прослушивания по завершённым попыткам с известной длительностью, без ошибок.
- `adjacent_artist_repeat_rate`, `unique_artists`, `top_artist_share`: повторы подряд,
  число исполнителей и доля самого частого исполнителя среди запусков волны.

«Новое» означает отсутствие в любимом, локальной коллекции и плейлистах на момент
рекомендации. Метрики учитывают только новые события с контекстом `wave` и
`playback_id`; исторические события не превращаются в вымышленные сессии.
При отсутствии знаменателя показатель равен `null`, а не нулю. Счётчики помогают
сравнивать версии, но сами по себе не доказывают причинное улучшение рекомендаций.

## Запуск и проверка изменений

Схема обновляется автоматически при следующем запуске сервера, существующая история
сохраняется. После обновления перезапустите сервер и обновите страницу плеера.

- Python/API: `venv/bin/python -m pytest -q`
- Очередь и счётчик прослушивания в JS: `npm test` (Node.js, без установки npm-зависимостей).

Все тесты БД используют временные базы; внешние сервисы в автоматических тестах подменены.
